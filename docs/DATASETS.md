# Datasets

A corpus of paired renders: a cheap picture, an expensive one, and the structure
the cheap one cannot see.

## One meadow

```text
  wrong                              right
  ─────                              ─────
  cheap  → generate scene A          generate scene ────┬─→ render cheap
  costly → generate scene B                             └─→ render costly
```

Generating twice looks safe. Placement is a pure function of world position, so
both runs would agree today.

It is not today's agreement that matters. It is that nothing can *later* make
them disagree — a quality tier that skips a fork, a rib count that moves a
vertex, an optimisation that reorders a draw. Any of those turns the pair into
two photographs of two different fields, and a network trained on that learns to
hallucinate rather than to reconstruct.

**The failure is silent.** The loss simply stops falling, and no image in the
corpus looks wrong.

So `RenderPair` holds an `Arc<TerrainScene>` and takes two *closures*. Both
renderers are handed the same scene by reference; neither can take ownership;
there is no constructor that accepts two scenes.

## Why the target is Cycles and not an expensive rasterisation

The rasteriser is fast enough to run in a game and cannot integrate a
hemisphere. Cycles integrates it and takes seconds. Learning the second from the
first is the entire point — so a corpus whose target was an expensive
*rasterisation* would be teaching a network to reproduce the approximations
rather than to replace them.

`--raster` falls back to that older pairing for when Blender is unavailable. It
is a convenience, not the corpus.

## Crops come from the middle of a larger bake

Every neighbourhood-reading term in the cheap renderer — occlusion, the relief
comparison, the shadows — is wrong near an edge. A corpus of crops baked at
their own size teaches a network that page borders exist, and it will
faithfully reproduce them.

So a shard bakes larger than it keeps and trims the margin from both halves.

## Every shard is its own world

Crops from one world share its regional hue, its density and its flow, so a
corpus drawn from a single seed is far less varied than its size suggests — and
a validation split cut from the same world is not a held-out sample at all.

## Layout

```text
000001/
  manifest.ron
  input/   beauty.png, material_weights.exr, elevation.exr, modifiers.exr
  target/  beauty.exr, albedo.exr, normal.exr, depth.exr, direct_diffuse.exr, …
  optional-scene/  manifest.json, geometry buffers
```

Two directories rather than a filename convention: a loader enumerates one side
at a time, and a prefix match over a flat directory is slower and easy to get
subtly wrong — `input-beauty.png` and `input-beauty-2.png` sort adjacently and
mean different things.

## The manifest pins everything

A corpus that cannot say what produced it can only be regenerated by guessing,
and a renderer under active development does not produce the same bytes next
month. That is not provenance for its own sake: **a model whose targets came
from two renderer versions has learned the average of two looks, and nothing in
the loss curve says so.**

So a shard records the document digest, the scene fingerprint, the root seed,
the bounds, the camera digest, the pixel scale, both renderer versions, the
Blender version, the render profile digest, every recipe version, the crop
margin, the pass list, a checksum per file — and the mark count.

The mark count is not decoration. A crop from a nearly empty scene is not a hard
example, it is a useless one, and a corpus with a hundred of them has a hundred
fewer shards than its directory listing suggests.

Checksums catch truncation. A short write is a black frame that nothing reports.

## Running it

```sh
terrain dataset --shards 64 --aovs --out target/corpus
terrain dataset --shards 8 --raster            # no Blender
terrain dataset --shards 8 --reference         # 512 spp targets
```

Shards are working state. A corpus is regenerated from a seed and a set of
versions, not archived.

## What is not here

The model. Neural rendering is the eventual consumer of this corpus and belongs
in its own repository — the terrain framework's job is to produce a trustworthy
corpus first, and pulling a training framework into this workspace before the
input/target contract has stabilised would fix the contract prematurely.
